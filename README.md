# MAC Changer

A small Python command-line tool that changes the MAC address of a network
interface on Linux. It reads the interface's current MAC address, applies a
new one (typed by you or generated at random) using `ifconfig`, then reads
the address again to check whether the change worked.

## Features

- Takes the interface and the new MAC address as command-line options
  (`-i/--interface` and `-m/--mac`), with `--help` output generated by
  `optparse`
- `-r/--random` generates a random MAC instead of `-m`: locally
  administered (cannot clash with a manufacturer-assigned address) and
  unicast (usable by a network card)
- Validates `-m` before running `ifconfig`: it must be 6 hex pairs
  separated by `:`, and the first pair must be even (unicast)
- Accepts uppercase, lowercase or mixed-case MAC addresses and compares
  them case-insensitively
- Exits with an error message if the interface is missing, if neither or
  both of `-m` and `-r` are given, or if the MAC address is invalid
- Reads and prints the interface's current MAC address before changing it
- Changes the MAC address by bringing the interface down, setting the new
  hardware address, and bringing it back up
- Checks the result of each `ifconfig` command; if setting the address
  fails, the interface is still brought back up so it is not left switched
  off
- Verifies the result by reading the MAC address again and reporting whether
  it matches the requested one
- Prints a clear error message instead of a traceback when the interface
  does not exist or `ifconfig` is not installed
- Exits with status `0` on success, `1` on failure and `2` for invalid or
  missing options, so it can be used from shell scripts
- Unit tests for validation, random MAC generation and the `ifconfig`
  commands, which run without root, Linux or `ifconfig`

## How to Run

Requirements:

- Linux with `ifconfig` available (on most distros it comes from the
  `net-tools` package)
- Python 3.6 or newer (the script uses f-strings)
- Root privileges, since changing a MAC address requires them

Run:

```bash
sudo python3 main.py -i eth0 -m 00:11:22:33:44:55
```

Replace `eth0` with your interface name (list them with `ifconfig`) and
`00:11:22:33:44:55` with the MAC address you want.

Use a random MAC address instead:

```bash
sudo python3 main.py -i eth0 -r
```

Show the help text:

```bash
python3 main.py --help
```

Example output:

```
[+] Current MAC address: 08:00:27:aa:bb:cc
[+] Changing MAC address for eth0 to 00:11:22:33:44:55
[+] MAC address successfully changed to the requested MAC address 00:11:22:33:44:55.
```

Run the tests (works on any OS, no root needed):

```bash
python -m unittest -v
```

## Known Issues / Limitations

- Linux only; it depends on `ifconfig`, which is not available on Windows and
  is deprecated on many newer Linux distros in favour of `ip`.
- Only `:` is accepted as a separator; `00-11-22-33-44-55` is rejected.
- The case-insensitive comparison works by lowercasing the input, which
  relies on `ifconfig` printing MAC addresses in lowercase (as net-tools
  does).
- The change is not permanent; the original MAC address returns after a
  reboot.
- Uses `optparse`, which is deprecated in favour of `argparse`.

## What I Learned

- Running system commands from Python with `subprocess.call` and capturing
  their output with `subprocess.check_output`
- Passing commands as a list of arguments instead of a single shell string
- Parsing command-line options and showing usage errors with `optparse`
- Using regular expressions (`re.search`) to extract a MAC address from
  command output
- Verifying that an action actually succeeded instead of assuming it did
- Checking command return codes, and making sure a failed step does not
  leave the system in a broken state (the interface switched off)
- Catching `CalledProcessError` and `FileNotFoundError` to show friendly
  errors instead of tracebacks
- Using exit codes with `sys.exit` so other programs can tell success from
  failure
- Using an `if __name__ == "__main__":` guard so the file can be imported
  without running
- Decoding command output with `.decode()`: calling `str()` on bytes gives
  the text of the bytes object (`b'...'` with literal `\n`), not the real
  output
- Using a regex character class (`[0-9a-fA-F]`) instead of `\w` to match
  only hex digits
- The difference between `re.search` (finds a match anywhere) and
  `re.fullmatch` (the whole string must match), and reusing one pattern
  for both
- What the two low bits of a MAC's first byte mean (multicast and locally
  administered), and setting or clearing single bits with `|`, `&` and `~`
- Validating user input early with `parser.error` instead of letting the
  system command fail
- Normalising input (lowercasing it once) so comparisons don't depend on
  how the user typed it
- Checking mutually exclusive options by hand, since `optparse` cannot
- Writing unit tests with `unittest`, using `subTest` to report the exact
  failing value in a loop
- Mocking `subprocess` with `unittest.mock.patch` so command-running code
  can be tested without running the real commands
